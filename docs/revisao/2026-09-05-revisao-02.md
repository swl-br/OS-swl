## R-15 — [ALTO] `init.asm` não monta `/dev` (devtmpfs); shell herda /dev sem dispositivos

- Componente: `userland/init.asm` (+ `build-rootfs.sh` em conjunto)
- Local: `init.asm:34-58` (só monta `/proc` e `/sys`)
- Severidade: **ALTO**
- Descrição: o `init` monta `proc` e `sysfs` mas nunca monta
  `devtmpfs` (ou `devfs`) em `/dev`. O `build-rootfs.sh` só cria nodes
  estáticos (`console`, `null`, `tty` — linhas 35-37). O kernel tem
  `CONFIG_DEVTMPFS=y`/`DEVTMPFS_MOUNT=y` (defconfig), então em muitos
  casos o kernel autopopula `/dev` no boot e cobre a lacuna — mas isso é
  indireto e depende da config; um shell interativo e apps que precisam
  de `/dev/tty*`, `/dev/input`, etc. não têm garantia. Na direção da GUI
  (A4) e do uso real, `/dev` precisa ser montado explicitamente.
- Responsável: camada userland inicial (pré-sessões registradas; sem dono
  no `docs/ai/sessions/`).
- Pedido: montar devtmpfs em `/dev` no `init.asm` antes de spawnar o shell.
- Status: ABERTO

## R-16 — [MÉDIO] Lacuna crítica de build: nenhum script gera `initramfs.cpio.gz`

- Componente: `Makefile` / `build-disk.sh` / repo (build system)
- Local: `Makefile:3,20-22`; `userland/build-disk.sh`
- Severidade: **MÉDIO** (bloqueia build limpo do zero)
- Descrição: o `target disk.img` do Makefile depende só de `boot.bin`/
  `stage2.bin`, mas o `build-disk.sh` recebe e exige o `$(INITRD)` e o
  `$(KERNEL)` (bzImage). **Não existe receita no repo que gere
  `build/initramfs.cpio.gz`** (busca por `initramfs`/`cpio` só acha o
  Makefile e o uso no build-disk.sh). O cpio que existia em `build/` foi
  produzido fora do repo — então um clone limpo + `fetch-deps.sh` +
  `make` **não reproduz o boot de forma completa** (builda boot/stage2/
  init, mas o disk.img falha por falta do INITRD).
- Responsável: build system inicial (pré-sessões); essencial para A4.
- Pedido: adicionar receita de geração do initramfs (ex.: montar o
  rootfs + `find | cpio` + gzip, ou `gen_init_cpio`), preferencialmente
  integrada ao `Makefile` com as dependências corretas.
- Status: ABERTO

## R-17 — [MÉDIO] INT15h AH=87h: limite de ~16MB por base de 24 bits

- Componente: `boot/stage2.asm`
- Local: `stage2.asm:228-240` (`set_src_base`/`set_dst_base`),
  `stage2.asm:335-349` (GDT 24-bit)
- Severidade: MÉDIO (limitação conhecida, não bug atual)
- Descrição: a relocação via `INT 15h AH=87h` usa descritores de memória
  com base de 24 bits. Endereços de destino/source acima de ~15MB têm o
  byte alto truncado silenciosamente. Hoje o kernel (1MB) + initrd cabem
  bem dentro, então funciona. Se um dia kernel/initrd somarem > ~15MB,
  o boot quebra de forma sutil e difícil de diagnosticar.
- Responsável: camada de boot (pré-sessões).
- Pedido: documentar como limitação conhecida, ou validar/tratar o caso
  de >16MB quando necessário (comentário no código).
- Status: ABERTO (documentação) / a depender — não bloquear boot atual

## R-18 — [BAIXO] `cmdline_str` força `console=ttyS0` — revisitado na fase GUI

- Componente: `boot/stage2.asm`
- Local: `stage2.asm:299` (`cmdline_str db 'console=ttyS0'`)
- Severidade: BAIXO (config, não bug)
- Descrição: o console do kernel vai só pra serial. Para a fase A4
  (GUI via DRM no boot real), será preciso também/alternativamente
  `console=tty0`/framebuffer. Registrar para quando A4 for implementada.
- Status: ABERTO (aguardando A4)

## R-19 — [BAIXO] `fetch-deps.sh`: não valida existência do kernel antes de `make`; URLs presumidas

- Componente: `userland/fetch-deps.sh`
- Local: linhas 25-43, 19-23
- Severidade: BAIXO
- Descrição: o script só baixa o kernel se `$KERNEL_DIR` não existe — se
  a árvore estiver presente mas incompleta/corrompida, não reconstrói.
  As URLs de kernel (v7.2.1) e versões de bash/busybox estão fixas; se
  alguma deixar de existir upstream, o script quebra silenciosamente.
- Pedido: checar também `arch/x86/boot/bzImage` para decidir se precisa
  baixar, e dar mensagem clara de erro de download.
- Status: ABERTO

## R-20 — [BAIXO] `init.asm`: `fork` em loop infinito se sempre falhar; falta `setsid`/controle de terminal

- Componente: `userland/init.asm`
- Local: `init.asm:60-74`
- Severidade: BAIXO
- Descrição: se `fork` retornar `<0` indefinidamente, o init fica em
  loop. E o shell não recebe `setsid`/controle de terminal explícito —
  como o projeto vai evoluir pra sessão gráfica (A4), o init exigirá
  `setsid`, /dev/console no stdin/stdout/stderr, e eventualmente subir
  o compositor em vez de (ou além de) um shell de serial.
- Pedido: revisitar quando A4 for implementada. Baixa prioridade agora.
- Status: ABERTO (aguardando A4)
